SOUL is an Android-first, SRM-only dating app built with Expo (SDK 57), TypeScript (strict), Expo Router and Supabase.

## Read before changing anything

- `PHASE_PLAN.md`: current phase, exit criteria, progress log
- `DECISIONS.md`: accepted decisions and unresolved configuration (`CONFIG_REQUIRED`)
- `SECURITY_MODEL.md`: trust boundaries, server-authoritative actions, RLS rules
- `MOBILE-DESIGN.md`: App Read, Nav Read, design dials, motion principles
- `ARCHITECTURE.md`: layers, folders, domain-to-backend map
- `skills/SOUL_SKILL_MAP.md`: which installed skills to use, and when

## Non-negotiables

- The APK is untrusted. Verification, credits, matches, entitlements, geofence and proximity are decided on the server only.
- Never put secrets in the app: only `EXPO_PUBLIC_SUPABASE_URL`, `EXPO_PUBLIC_SUPABASE_ANON_KEY` and `APP_ENV`.
- No raw location of another user ever reaches a client. Distance is bucketed; bearing is quantized.
- Monochrome only. Colours, type, spacing and motion come from `src/theme` tokens. The lint rule rejects hex literals outside `src/theme`.
- Use the supplied logo asset (`assets/brand`) as is. Never recreate it with a font.
- No human sample names anywhere (use `User A`, `Profile 01`, `Test User 01`).
- No feature creep (spec section 57). Product rules are not changed silently: record any interpretation in `DECISIONS.md`.

## Expo has changed: do not trust training data

Before writing code that touches an Expo, EAS or React Native API:

1. Read the `expo` major version in `package.json` (57).
2. Fetch the versioned docs, `https://docs.expo.dev/versions/v57.0.0/`, not `latest`.
3. For anything else, use https://docs.expo.dev/llms.txt and follow its links.

## Commands

```bash
npx expo install <package>   # always, so versions match SDK 57
npm run typecheck            # tsc --noEmit
npm run lint                 # expo lint
npm test                     # jest (jest-expo)
npm run format:check
npx expo prebuild --platform android   # regenerate ./android (git-ignored, never hand-edited)
npm run android:build        # memory-capped dev build (emulator + Docker stopped), installs if a device is up
npm run emulator             # boot the D:-based emulator
npm start                    # Metro for the dev client
```

Android builds must use JDK 17: `JAVA_HOME="C:/Program Files/Eclipse Adoptium/jdk-17.0.20.1+1"`. The system default is JDK 25, which the Android toolchain does not use.

**Disk rule: C: is nearly full. Never write heavy dev data to C:.** On 2026-09-27, C: hit 100 % during a Docker image pull and Docker's storage failed. All SOUL caches live on D:
- npm cache: `D:/soul-dev/npm-cache` (project `.npmrc`)
- Gradle: `GRADLE_USER_HOME=D:/soul-dev/gradle` for every Gradle or `expo run:android` command
- Emulator: SDK root `D:/soul-dev/android-sdk` (emulator and system image) and `ANDROID_AVD_HOME=D:/soul-dev/avd`
- Docker Desktop disk image: **moved to `D:/soul-dev/docker/wsl`** (`CustomWslDistroDir` in `%APPDATA%/Docker/settings-store.json`; backup at `settings-store.json.soul-backup`)

Check free space (`df -h /c`) before any large download.

**Memory rule: RAM is 15 GB and the Windows page file lives on C:.** Docker's VM (up to 8 GB), the emulator (3 to 4.6 GB) and a native Gradle build together exhaust memory, grow the page file on C:, and fail builds with "The paging file is too small". Therefore:
- Never run a native Gradle build while the emulator or Docker is running. `npm run android:build` is memory-capped (`--max-workers=4`, 2 GB heap, in-process Kotlin) and stops its daemons afterwards.
- Run the app with `npm run db:start` + `npm run emulator` + `npm start` only after the build.
- Stop the Gradle and Kotlin daemons after builds.

Run typecheck, lint and tests before declaring any task done, and update `PHASE_PLAN.md`.

## Structure

- `src/app`: routes only. Route groups `(auth)`, `(onboarding)` and `(app)/(tabs)` are guarded by server account status.
- `src/features/<domain>`: screens, components, API hooks, models.
- `src/components`: shared `Soul*` primitives. `src/theme`: tokens.
- `supabase/`: migrations, Edge Functions, seed, tests. DB commands: `npm run db:start | db:reset | db:test | db:types | db:verify` (see SUPABASE.md).
- `./android` is generated by prebuild (Continuous Native Generation). Configure native behaviour through `app.config.ts` and config plugins only.
